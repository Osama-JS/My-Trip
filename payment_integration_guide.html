دليل دمج الدفع للتطبيق الجوال

شرح متكامل لآلية الربط مع Tabby, Tamara, و HyperPay

نظرة عامة على دورة الدفع

تعتمد عملية الدفع في التطبيق على مبدأ "بدء الجلسة بالسيرفر -> الدفع في الويب -> التحقق النهائي".

sequenceDiagram participant Mobile as التطبيق (App) participant Server as سيرفر My-Trip participant Gateway as بوابة الدفع (Tabby/Hyper) Mobile->>Server: 1. طلب بدء الدفع (initiate) Server->>Gateway: طلب جلسة دفع Gateway-->>Server: رقم الجلسة / رابط التوجيه Server-->>Mobile: رد ببيانات الدفع Mobile->>Mobile: 2. فتح WebView للدفع Mobile->>Gateway: إتمام عملية الدفع Gateway-->>Mobile: توجيه للرابط (Success/Fail) Mobile->>Server: 3. طلب التحقق (verify) Server->>Gateway: التأكد من حالة العملية Server-->>Mobile: رد بالنتيجة النهائية وتحديث الحجز

1. بدء الدفع (Initiation)

عندما يختار المستخدم طريقة دفع ويضغط "دفع"، يجب استدعاء:

Endpoint POST /api/payment/initiate

HyperPay (Visa/Mada)

سيعيد السيرفر checkout_id.

{ "checkout_id": "xyz123...", "script_url": ".../paymentWidgets.js" }

الإجراء: استخدم الـ ID لتحميل نموذج الدفع.

Tabby / Tamara

سيعيد السيرفر web_url (رابط مباشر).

{ "payment_id": "pk_...", "web_url": "https://checkout.tabby.ai/..." }

الإجراء: افتح الرابط في WebView داخل التطبيق.

2. التعامل مع الـ WebView

في حالات Tabby و Tamara، يجب على التطبيق مراقبة روابط العودة (Navigation Events):

  • رابط النجاح: يحتوي عادة على status=success.
  • رابط الفشل: يحتوي على status=failure.
  • رابط الإلغاء: يحتوي على status=cancel.

بمجرد وصول الـ WebView إلى أحد هذه الروابط، يجب إغلاقه والعودة لواجهة التطبيق.

3. التحقق النهائي (Verification)

هام جداً: لا تعتمد على إغلاق الـ WebView فقط لتأكيد الدفع. يجب استدعاء endpoint التحقق للتحديث في قاعدة البيانات المحلية.

Endpoint POST /api/payment/verify
// مثال لطلب التحقق (Tabby/Tamara) { "payment_type": "tabby", "payment_id": "id_returned_from_webview" }
// مثال لطلب التحقق (HyperPay) { "payment_type": "mada", "checkout_id": "id_from_initiate" }

توصيات للمطورين (UX/UI Best Practices)

!
حالة الانتظار (Loading States): أظهر مؤشر تحميل عند التحقق من الدفع، ولا تسمح للمستخدم بالعودة للخلف أثناء تحديث السيرفر.
✓
التزامن التلقائي: السيرفر مربوط بـ Webhooks، لذا حتى لو أغلق المستخدم التطبيق، سيتم تحديث حالة الحجز تلقائياً فور نجاح العملية.
