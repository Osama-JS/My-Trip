تعليمات واجهة Sitata API

كيفية دمج خدمة تأمين السفر واشتراكات الحماية المدمجة (Embedded Insurance)

المقدمة المصادقة والأخطاء دليل دمج التأمين

نظرة عامة على خدمة التأمين (Travel Safe Subscriptions)

تتيح لك Sitata API إعادة بيع (Resell) اشتراكات الحماية وتأمين السفر كخدمة مدمجة (Embedded) داخل منصتك (للطيران، الفنادق، أو البكجات السياحية). تعتمد الآلية القياسية على أربع مراحل برمجية:

  1. التسعير (Quoting): الاستعلام عن سعر الوثيقة التأمينية بناءً على تفاصيل الرحلة (التواريخ، الوجهة، أسعار التذاكر).
  2. الإنشاء المؤقت (Staging): إنشاء سجل مبدئي للتأمين قبل دفع العميل لضمان حجز السعر.
  3. الإصدار (Issuance): تأكيد الدفع وإصدار وثيقة التأمين رسمياً للمسافر.
  4. الإلغاء (Cancellation): في حال ألغى العميل حجزه الرئيسي، يتم إلغاء الوثيقة من Sitata.

تفصيل العمليات وكيفية ربطها بمشروعك (My-Trip)

1. دمج التأمين مع البكجات السياحية (Trips & Packages)

1
التهيئة وعرض السعر (UI Phase): في تطبيق الجوال، عندما يختار المستخدم باقة سياحية، قم بعرض خيار "إضافة تأمين شامل". نظراً لأن الوجهة والمدة وتواريخ البكج معروفة، يقوم الـ Backend الخاص بك بإرسال طلب (POST /quote) لـ Sitata لحساب السعر، وإعادته لتطبيق الجوال لعرضه وتجميعه مع المبلغ الإجمالي.

2. دمج التأمين مع رحلات الطيران (Flights)

2
حماية التذكرة: في شاشة إدخال بيانات الركاب للطيران، يتم استخدام أعمار الركاب ووجهة الوصول لاستدعاء الـ API. يركز التأمين هنا بشكل أساسي على (إلغاء الرحلة لظروف طارئة، أو فقدان الأمتعة).

3. دمج التأمين مع الفنادق (Hotels)

3
تأمين الإلغاء (Cancellation Protection): للفنادق، يتم تمرير إجمالي تكلفة الإقامة لـ Sitata لتقييم سعر الحماية. إذا ألغى العميل حجزه خارج فترة السماح المجانية، يضمن له هذا التأمين استرداد جزء كبير من أمواله.

الآلية البرمجية (الربط التقني)

لتنفيذ هذه العمليات بشكل دقيق، يجب إنشاء كلاس أو خدمة في Laravel (مثلاً: SitataInsuranceService) تتولى الاتصال مع نقاط نهاية (Endpoints) Sitata. ملاحظة: هذا الكود للتوضيح المعماري للتدفق.

دالة الحصول على السعر (Quoting)

// يتم إرسال طلب إلى واجهة التسعير في Sitata // Endpoint: POST https://api.sitata.com/v1/insurance/quote // Headers: Authorization, Organization { "destination_country": "ES", "departure_date": "2026-07-01", "return_date": "2026-07-15", "total_trip_cost": 5000.00, "travellers": [ { "age": 30 }, { "age": 28 } ] }

الشرح (Arabic Explanation): تقوم هذه العملية بإرسال بيانات مبسطة عن الرحلة (دولة الوصول، تواريخ الرحلة، وتكلفة الرحلة الإجمالية، وأعمار المسافرين). يقوم نظام Sitata بالرد مباشرة بسعر التأمين المناسب (Premium) لهذه المعطيات.

دالة الإصدار الفعلي (Issuance) بعد الدفع

هذه الدالة يجب ألا يتم استدعاؤها إلا بعد نجاح الدفع (Payment Webhook / Success Callback) الخاص بالبوابة (مثلاً في PaymentWebController).

// يتم إرسال بيانات كاملة لإصدار الوثيقة // Endpoint: POST https://api.sitata.com/v1/insurance/policies { "quote_id": "qt_123456789", "booking_reference": "MYTRIP-FL-0099", "travellers": [ { "first_name": "Osama", "last_name": "Alsamomy", "email": "osama@example.com", "passport": "AB1234567", "nationality": "SA" } ] }

الشرح (Arabic Explanation): بعد الدفع، يتم تزويد Sitata بالمعلومات الشخصية الفعلية للمسافرين لربطها بوثيقة التأمين (Policy). ستقوم واجهة Sitata بالرد برقم الوثيقة policy_number ورابط (URL) لملف الـ PDF الخاص بها. يجب عليك حفظ هذا الرقم في قاعدة البيانات الخاصة بك وإرسال ملف الوثيقة للمسافر عبر البريد الإلكتروني.

دالة الإلغاء (Cancellation)

// Endpoint: DELETE https://api.sitata.com/v1/insurance/policies/{policy_id}

الشرح (Arabic Explanation): إذا قام العميل بطلب إلغاء الحجز عبر تطبيق My-Trip ضمن فترة السماح (Cooling-off Period) وتمت الموافقة، يجب استدعاء هذه النقطة في الخلفية لإشعار Sitata بإلغاء وثيقة التأمين واسترداد القيمة لتعويض العميل.
