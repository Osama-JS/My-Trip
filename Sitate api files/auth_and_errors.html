تعليمات واجهة Sitata API

آلية المصادقة، الرموز المميزة (Tokens)، والأخطاء الشائعة

المقدمة المصادقة والأخطاء دليل دمج التأمين

آلية المصادقة (Authentication)

تستخدم Sitata مفاتيح API (API Keys) للسماح بالوصول. يجب إدراج مفتاح الـ API في ترويسة الطلب (Header) كالتالي:

Authorization: TKN API_KEY_HERE

بالإضافة لذلك، بصفتك طرفاً ثالثاً، يجب عليك إرفاق معرف الشركة (Company ID) في جميع الطلبات كالتالي:

Organization: COMPANY_ID_HERE
تحذير أمني: إياك أن تكشف مفتاح الـ API السري الخاص بشركتك في التطبيقات التي يواجهها المستخدم (مثل تطبيق الجوال). استخدم مفتاح الـ API فقط في الـ Backend الخاص بك (السيرفر).

استخدام المستخدم النهائي مقابل الشركة (Company vs. End User)

يتم تصميم بعض نقاط النهاية للشركة (تُعامل عبر النطاق org) وتتطلب توثيقاً بمفتاح الشركة. أما النقاط الأخرى فمصممة لتستخدم من قبل المسافر باستخدام الـ Token الخاص به.

حالة الاستخدام النموذجية (Typical Use Case):

  1. قم بإنشاء سجل مسافر (Traveller Record) باستخدام نقطة نهاية الشركة، واحتفظ بـ authentication_token الخاص به في قاعدة بياناتك.
  2. قم بإنشاء رحلة (Trip) باستخدام نقطة نهاية الشركة والمسافر الذي تم إنشاؤه.
  3. استخدم authentication_token الخاص بالمسافر للوصول إلى بقية الخدمات مثل تفاصيل الأمراض، التنبيهات، وغيرها وعرضها في التطبيق.

دعم اللغات (Language)

تدعم Sitata اللغة الإنجليزية والإسبانية بشكل رسمي، وهناك دعم جزئي للغات أخرى. لتغيير لغة الاستجابة، يجب إرسال الترويسة التالية استناداً إلى معيار ISO_639-1 (مثل ar للعربية إن وجدت، أو en للإنجليزية):

Accept-Language: en

رموز الأخطاء الشائعة (Error Codes)

أثناء التعامل مع الـ API، قد تواجه الأخطاء التالية:

كود الخطأ المعنى والتوضيح
400 طلب غير صالح (Bad Request): البيانات المرسلة غير صحيحة أو ناقصة.
401 غير مصرح (Unauthorized): مفتاح الـ API خاطئ أو منتهي الصلاحية.
403 ممنوع (Forbidden): ليس لديك الصلاحية للوصول إلى هذا المورد.
404 غير موجود (Not Found): المورد المطلوب غير موجود في النظام.
429 طلبات كثيرة (Too Many Requests): قمت بتخطي الحد المسموح به من الطلبات. يرجى الإبطاء.
500 خطأ في السيرفر (Internal Server Error): مشكلة من جهة خوادم Sitata.
