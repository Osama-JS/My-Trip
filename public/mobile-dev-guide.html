دليل التكامل - تطبيق الموبايل

شرح تفصيلي لآلية حجز الطيران والفنادق وعمليات الدفع الموحدة

نظرة عامة على الهيكلية

تم توحيد بنية الدفع في الـ API لتكون مستقلة تماماً عن التطبيق (Decoupled). هذا يعني أن التطبيق لا يحتاج إلى دمج حزم دفع معقدة (SDKs) مثل HyperPay أو Tamara. كل شيء يتم من خلال الـ API وإعادة التوجيه (WebView).

الهدف الرئيسي: توفير تجربة دفع موحدة لجميع الخدمات (طيران، فنادق، رحلات) وتسهيل إضافة وسائل دفع جديدة مستقبلاً دون الحاجة لرفع تحديث جديد للتطبيق على المتاجر.

مسار عمليات الحجز (الطيران والفنادق)

سواء كان المستخدم يحجز رحلة طيران عبر /api/flights/book أو فندقاً عبر /api/hotels/book، فإن الاستجابة الناجحة (Response) ستحتوي دائماً على كائن payment_info.

المطلوب من مطور الموبايل (الخطوات)

  • استقبال الطلب: بعد نجاح طلب الـ API للحجز، قم بالتحقق من وجود الكائن data.payment_info.methods.
  • عرض وسائل الدفع: قم بعرض قائمة منسدلة من الأسفل (مثلاً BottomSheet في Flutter/GetX) تحتوي على وسائل الدفع المتاحة بناءً على مصفوفة methods. استخدم الـ logo لرمز وسيلة الدفع والـ name للاسم.
  • فتح نافذة الدفع (WebView): عند ضغط المستخدم على إحدى وسائل الدفع، قم بفتح الرابط الموجود في الـ url الخاص بتلك الوسيلة داخل WebView مدمج في التطبيق.
  • مراقبة مسار الرابط (URL Interception): داخل الـ WebView، يجب مراقبة الروابط التي يتم إعادة التوجيه إليها لاكتشاف نجاح أو فشل العملية.
دعم النسخ القديمة (Backward Compatibility): إذا كان التطبيق يستخدم الإصدار القديم، سيعتمد على متغير payment_url المباشر والذي يوجه المستخدم للبطاقة الائتمانية بشكل افتراضي.

مراقبة الروابط (WebView Callbacks)

عندما يكمل المستخدم عملية الدفع بنجاح أو تفشل العملية، سيقوم السيرفر بإعادة توجيهه إلى روابط محددة. يجب على التطبيق (WebView) التقاط هذه الروابط لإغلاق النافذة وإظهار رسالة للمستخدم.

الحالة الرابط المتوقع (URL pattern to match) الإجراء في التطبيق
النجاح (Success) /payments/success أو status=success إغلاق الـ WebView وإظهار صفحة "تم الحجز بنجاح"
الفشل (Failed/Error) /payments/error أو status=failed إغلاق الـ WebView وإظهار رسالة "فشلت عملية الدفع"
الإلغاء (Cancel) /payments/cancel إغلاق الـ WebView والعودة لشاشة تفاصيل الحجز

مثال برمجي مبسط (Flutter / webview_flutter)

NavigationDecision _interceptNavigation(NavigationRequest request) {
  if (request.url.contains('/payments/success')) {
    // 1. Close WebView
    Get.back();
    // 2. Show Success Screen
    Get.to(() => BookingSuccessScreen());
    return NavigationDecision.prevent;
  }
  
  if (request.url.contains('/payments/error') || request.url.contains('/payments/cancel')) {
    Get.back();
    Get.snackbar('Error', 'Payment failed or was cancelled');
    return NavigationDecision.prevent;
  }
  
  return NavigationDecision.navigate;
}

ملخص القواعد الذهبية لمطور التطبيق

  1. لا تبرمج واجهات الدفع (UI) الخاص ببيانات البطاقة داخل التطبيق نهائياً. استخدم دائماً الـ WebView.
  2. اعتمد دائماً على مصفوفة methods المرسلة من الـ API لبناء خيارات الدفع، فلا تقم بتثبيت (Hardcode) أي وسيلة دفع في كود التطبيق.
  3. تأكد من تمرير لغة التطبيق الصحيحة في الهيدر Accept-Language: ar/en لضمان ظهور واجهة الدفع في الويب بنفس لغة التطبيق.
  4. الـ type المدمج في الرابط يعالج مسألة التفريق بين حجز الفنادق أو الطيران من طرف السيرفر، فلا تشغل بالك بتتبعه كمتغير مستقل.
